### Медиа-выравнивание (VideoGroup + ImageRow)
- `VideoGroup` и `ImageRow`: добавлен `sm:justify-center sm:items-center` — одиночные или
  узкие блоки центрируются по ширине секции.
- **isSingleHorizontal**: 1 горизонтальное видео → высота ×1.3 (300→390px, ширина ~693px).
  Множитель 1.5 был отклонён → 1.3 утверждено.
- **Media-секция** (конец страницы кейса): `grid sm:grid-cols-2` → `flex flex-wrap justify-center`.
  При 1 видео: `sm:h-[390px] sm:w-auto` (совпадает с isSingleHorizontal) → центрируется и
  одинаковая ширина со Strategy-видео. При 2: `sm:w-[48%]`.
- **2-item rows** (ImageRow и VideoGroup при `length === 2`): `sm:w-auto` → `sm:flex-1 sm:min-w-0` —
  оба ряда растягиваются на полную ширину контейнера → ширина ImageRow = ширина VideoGroup.
- **aside-right / aside-left**: `items-start` → `items-center` (текст вертикально по центру картинки).
- **video-image layout**: `sm:items-start` → `sm:items-center sm:justify-center`.

### ImageRow: пропорциональный flex по aspect ratio
- Проблема: `priem-execution-tall.jpg` — очень высокое вертикальное фото. При `flex-1` (равные 50%)
  оно занимало половину ряда и сильно кропалось по высоте. Узкое по природе изображение не должно
  занимать ту же ширину, что широкое.
- Решение: `ImageRow` переписан — при 2+ фото каждое получает `flex-grow = src.width / src.height`
  (aspect ratio оригинала). Широкое фото (~1.78) → ~73% ряда, вертикальное (~0.67) → ~27%.
  Высота фиксирована `--row-h`, вертикальная картинка "поджимается" ею.
  Реализовано через CSS-переменную `--r` и scoped `<style>` с `@media (min-width: 640px)`.
  Детали — `ASTRO-EDUCATION.md` §13.7.

**ПРОБЛЕМА — деплой падает.** Деплой настроен **автоматом из GitHub**. Лог сборки в Cloudflare ругается
(Wrangler):
```
"name": "worker-name", "compatibility_date": "2026-05-31", "main": "src/index.ts"
If you are uploading a directory of assets, you can either:
 - npx wrangler versions upload --assets=./dist
 - Or create a "wrangler.jsonc": { "name": ..., "assets": { "directory": "./dist" } }
```

**ДИАГНОЗ (рабочая гипотеза):** это ошибка **Wrangler `deploy`/`versions upload`**, а не Pages-пайплайна.
Значит репозиторий подключён как **Workers project** (новый «Import a repository» под Workers Builds),
который по умолчанию гонит `npx wrangler deploy` и требует `wrangler.jsonc` с `main` (скрипт воркера)
ИЛИ `assets.directory`. Для нашей чистой статики (`output: static` → `dist/`) воркер-скрипт не нужен —
нужен только assets-деплой.

**Что уже сделано в этой сессии:** создан `wrangler.jsonc` в корне:
```jsonc
{ "name": "maria-portfolio", "compatibility_date": "2026-06-01", "assets": { "directory": "./dist" } }
```
`wrangler.jsonc` УЖЕ закоммичен (в `9666ea4`, дерево чистое).
⚠️ НО: (1) `"name"` (`maria-portfolio`) должно совпадать с реальным именем проекта в дашборде Cloudflare —
проверить/исправить; (2) при Workers-сборке нужно ещё задать **build command = `npm run build`** в настройках
проекта (иначе `dist/` не создастся перед деплоем); (3) если выберем путь Pages — `wrangler.jsonc` удалить.

### Про будущую видеоплатформу (зафиксировано на будущее, НЕ делаем сейчас)
- Требование «нельзя собрать исходник из стрима» = нужен **настоящий DRM** (Widevine/FairPlay/PlayReady).
  Без DRM HLS-сегменты склеиваются обратно. AES-128 HLS — лишь «защита от ленивых».
- Managed-провайдеры с DRM: Cloudflare Stream (дёшево), Mux (лучший DX), Bunny, Vimeo Enterprise.
- Слои: сегментный стриминг → подписанные URL с TTL → ограничение по домену → forensic watermark → DRM.
- Полный захват экрана предотвратить нельзя в принципе — только повышать стоимость взлома.
